1. **Frame-range inconsistency:**

2. **Two different rate fields:**
   `recordInfo/recordRate = 10000`, corroborated by MII.

3. **No verified physical calibration:**

   Do not assume an 8-bit AVI retains all 12-bit camera information or represents untouched acquisition data.

## 5. Problem statement

> Develop and validate a reproducible method to locate RBCs in high-speed microscopy recordings, maintain their identities across consecutive frames, and estimate their trajectories and speeds as they pass through a narrow tube/channel.

Separate the problem into:
1. **Preprocessing:** improve useful contrast without distorting measurements.
2. **Detection/segmentation:** locate the cell in each frame.
3. **Tracking:** associate the same cell across frames.
4. **Measurement and validation:** calculate supported quantities and check whether the track is correct.

The immediate engineering goal is:

> Create a manageable, scientifically useful working sample and a simple experiment loop before processing entire recordings.

**A large file on disk does not need to be loaded entirely into RAM.** Read frames incrementally.

## 6. Agreed approach and constraints

The agreed starting workflow is:

**Inspect a sample → try preprocessing → test one understandable tracker → visually check results → save the experiment.**

Prefer:
- Colab as the initial workbench.
- Short, **contiguous sequences** at original resolution and frame cadence.
- A channel-focused region of interest where useful.
- Simple classical methods before assuming deep learning is necessary.
- Manual reference positions for a few trajectories.
- Lightweight automatic run records.

Avoid:
- Blindly reducing resolution or skipping frames.
- Using a lossy preview as scientific analysis data.
- Choosing a final algorithm from one still image.
- Reporting physical speed before timing and spatial calibration are verified.
- Overwriting raw files or the existing download notebook.
- Uploading research footage to additional AI providers or making data public without permission.

## 8. Tracking approaches discussed—not yet selected or validated

### A. Click-initialized template matching
Manually select the target cell once, then search for a similar image patch in nearby frames, constrained to the tube.

Potential advantages:
- Simple first experiment for one cell.
- Avoids needing a perfect whole-image detector.

Risks:
- Cell deformation or contrast changes.
- Drift.
- Strong stationary wall edges dominating the match.

### B. Detection plus centroid linking
Candidate pipeline:

**Channel mask → background correction if justified → cell detection → centroid positions → frame-to-frame linking**

Start with simple linking; introduce motion prediction and consistent assignment if necessary.

Risks:
- Cell/wall confusion.
- Overlaps.
- Inconsistent segmentation as the cell changes shape.
- Background subtraction suppressing stationary cells.

### C. Tube-aligned kymograph
Extract image intensity along a strip following the tube and stack it over time. A moving cell may create a trace whose position changes with time.

Potential use:
- Understand the passage visually.
- Estimate along-channel motion.
- Cross-check another tracker.

Limitations:
- Requires a distinguishable cell signal.
- Multiple cells can produce ambiguous traces.
- Does not by itself recover the full 2D trajectory.

### D. Motion-aware/keyhole tracking
Use recent movement to constrain likely next positions. Relevant if simple linking fails.

### E. Existing tools
Fiji/TrackMate can provide detection, linking, overlays, and manual correction:
https://imagej.net/plugins/trackmate/

Deep learning remains an option if simpler detection methods fail, but no need for it has been established.

## 9. Research papers and code found

### Recommended first paper
**Kumar et al., 2020 — Automated Motion Tracking and Data Extraction for Red Blood Cell Biomechanics**
https://doi.org/10.1002/cpcy.75

Close match:
- High-speed microscopy of RBCs in constricting microchannels.
- 8-bit grayscale AVI.
- Position, velocity, and morphology extraction.

Workflow:
**Background/static-object removal → filtering/contrast → channel ROI → segmentation → size filtering → tracking → export**

Uses commercial **Image-Pro** and discusses Fiji alternatives. Read *Basic Protocol 1* and *Basic Protocol 2* first. Borrow the workflow, not the exact thresholds.

### Relevant tracking-method paper
**Automatic tracking and deformation measurements of red blood cells flowing through a microchannel with a microstenosis: the keyhole model — 2014**
https://doi.org/10.1080/21681163.2014.957868

Describes MATLAB-based RBC tracking and deformation measurement through a smooth contraction using the keyhole model.

The abstract/method description was verified; **downloadable implementation was not verified**.

### Public Python project
**RBCZigZagAI**
https://github.com/berndporr/RBCZigZagAI

Companion paper:
**Link et al., 2023 — AI based image analysis of red blood cells in oscillating microchannels**
https://pubs.rsc.org/en/content/articlehtml/2023/ra/d3ra04644c

Relevant files:
- `framegenerator.py`: AVI reading and background calculation.
- `celldetect.py`: cell detection at selected channel positions.
- `imageobt.py`: extraction of relevant cell images.
- `train.py`: classification model training/testing.

The paper describes OpenCV background subtraction, localized detection windows, contour detection, and cropping.

**Critical distinction:** Its final task is native-versus-chemically-modified RBC classification, **not complete identity-preserving trajectory/speed tracking**. Reported classification accuracy is not tracking accuracy.

The repository and paper were reviewed at the description/method level. **The source implementation has not been thoroughly inspected or run.** Retrieved information described the repository as archived; verify its current status before reuse.

### Reference dataset
**RBCdataset**
https://github.com/icimrak/RBCdataset

Contains two partially annotated microfluidic cell-flow sequences, with bounding boxes and track identities.

Useful for understanding annotations or testing algorithms. **It is a dataset, not a ready-made tracker**, and success on it does not establish success on our recording.
